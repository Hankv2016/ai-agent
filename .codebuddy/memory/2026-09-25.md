## run.bat 编码坑（重要）
- 中文 Windows 的 `cmd.exe` 解析 .bat 时按 GBK(cp936)，**UTF-8 无 BOM 且含中文的 bat 会被错读**，中文注释/`if exist` 等被错误分词成命令而报一堆乱码错误（如 `'NAI_MODEL...REM'`、`'exist'`、`'柟寮忥細'`）。
- 解决：`run.bat` 改为**纯 ASCII（英文）**即可零风险。若坚持要中文提示，须把 bat 另存为 GBK 或带 BOM 的 UTF-8。
- 末尾的 `libpng warning: iCCP: known incorrect sRGB profile` 是 PyQt 加载 PNG 资源的无害警告，可忽略。

## QTextEdit 块排版规则（实测，重要）
用户反馈历史框排版粘连（`hiAI： Hello!...`）。offscreen 实验结论（PyQt5）：
- **连续多次 `insertHtml` 会并进同一个块**（'你：','hi','AI：' 全在一行）——即使 HTML 全部闭合。
- 单次 `insertHtml` 内含多个块级标签（`<p>A</p><p>B</p>`）→ 正常分行。
- `QTextEdit.append()` 每次保证从**新段落**开始 → 逐段追加用它。
- **`QTextEdit` 没有 `appendHtml` 方法**（会 AttributeError）。
- 尾部替换（setPosition+removeSelectedText）后直接 `insertHtml` 会粘到上一块（'C1C2'）；**必须先 `cursor.insertBlock()` 再 `insertHtml`**。
- 落地：`_append_user`/`_begin_ai` 用 `append()`；`_render_ai` 替换后 `insertBlock()+insertHtml()`；标签行与 markdown 内容分开插入，避免外层 `<p>` 嵌套内层 `<p>` 的非法 HTML。`_smoke.py` 已加 `LAYOUT_OK` 行序断言。

## 远程图片内嵌显示修复（同日，推翻上面"Qt 自动加载"的假设）
- 用户实测：远程 `<img>` 显示破图占位符 → Qt 的 `QTextDocument.loadResource` 默认**不下载 http(s) 资源**（只查本地资源表），需自己实现下载。
- 方案：`QNetworkAccessManager` 异步下载 → `QImage.loadFromData(reply.readAll())` → `document().addResource(QTextDocument.ImageResource, QUrl(url), img)` → `doc.markContentsDirty(0, doc.characterCount())` 触发重排。新增 `_register_remote_image` / `_on_image_downloaded` / `_refresh_doc_layout`，`_append_user` 渲染每张图后调用注册；`_img_cache`（url→QImage）避免重复下载、重绘（`clear()` 会清文档资源）后缓存命中即时重注册。`markContentsDirty` 不改文档结构，不会破坏 AI 流式输出的 `_ai_doc_pos`。
- 新增导入：QtCore `QUrl`、QtGui `QImage, QTextDocument`、QtNetwork `QNetworkAccessManager/Request/Reply`。`_smoke2.py` 加 `REMOTE_IMG_OK` 断言，回归全过。

## 修正：该方案导致"输入图链接点发送无报错闪退"（C++ 崩溃），已回退
- 现象：输入图链接点发送，进程直接退出，无 Python 异常（非 `_save_current_session` 那种 list.strip 错）。
- 根因：对话控件已从 `QTextEdit` 换成 `QTextBrowser`；`QTextBrowser` 会**原生自动加载 `<img src="http(s)">` 远程图片**，而我上一轮又额外加 `QNetworkAccessManager` 下载 + `document().addResource(ImageResource, QUrl(url), img)` + `markContentsDirty`。两条路径对同一 URL 并发/重入加载 → 段错误。
- 修复：回退自定义下载/注册/重排机制（删 `_register_remote_image`/`_on_image_downloaded`/`_refresh_doc_layout`、`_img_cache`/`_img_pending`/`_nam` 状态，及 QtNetwork/QImage/QTextDocument/QUrl 导入），图片改由 `QTextBrowser` 原生异步加载。代价：图片显示依赖原生网络加载与 URL 可达性（不可达则破图但不崩）。
- 教训：`QTextBrowser` 与 `QTextEdit` 对 `<img>` 远程资源处理不同；切勿与控件原生加载并行再手动 `addResource` 远程 URL。若需"确保显示不可达/防盗链图片"，应子类化 `QTextBrowser` 重写 `loadResource` 禁用其 http 自动加载，并改用本地临时文件 `file://` 内嵌。
- 仍保留 `faulthandler` 写 `gui_crash.log` 与 `sys.excepthook` 弹窗作为崩溃兜底。

## 破图修复（同日，闪退解决后）：绕过 QTextBrowser 原生 https 加载
- 现象：闪退解决后，输入图链接缩略图显示破图（`QTextBrowser` 原生加载 https 图片失败）。
- 根因推断：`QTextBrowser` 原生加载 https `<img>` 依赖 Qt 自带 OpenSSL；该 PyQt5/Python314 环境很可能缺或 SSL 库不匹配 → 拉不到图。浏览器用系统 SSL 能开。
- 方案：**`<img>` 的 src 改用自定义本地 key（如 `imgcache://<md5(url)>`），不走 Qt 的 http(s) 加载路径**；图片用 Python `urllib.request`（自带 SSL，通常可用）在 `threading` 子线程下载，`QImage.loadFromData` 解码后主线程 `document().addResource(ImageResource, QUrl(key), img)` + `markContentsDirty` 注册显示。彻底规避双重加载（之前崩溃源）与 Qt SSL 缺失。
- 实现要点：`_img_key`/`_download_image_async`/`_fetch_image`/`_apply_image`（pyqtSlot+QMetaObject.invokeMethod QueuedConnection 回主线程）；`_append_user` 渲染时 `<a href=真实url>` 仍可点击系统浏览器打开；`_redraw_all` 重绘时缓存命中即时注册。imports 加 urllib/threading/hashlib 及 QUrl/QMetaObject/Qt/Q_ARG/pyqtSlot/QImage/QTextDocument。
- 若仍破图：多半是 URL 防盗链/403（连 Python urllib 也被拒），非代码问题；届时可换图源或加 Referer/代理，或改存本地 `file://` 内嵌（当前 key 方案已足够，file:// 非必需）。
