## run.cmd 启动报错修复（同日）
- 现象：用户输入 `run` 执行 `run.cmd`，报 `'KEY'/'EVERY'/'.txt'/'openai" >nul 2>&1' 不是内部或外部命令` —— 脚本注释词被当命令执行。
- 根因：`.cmd` 文件在 Windows `cmd` 下默认按系统编码（GBK/CP936）读取。原 run.cmd 含**中文注释 + 半角括号 `()`**；UTF-8 中文在 GBK 下乱码，且半角 `()` 被 cmd 当成代码块语法解析，导致 REM 注释行被拆成命令。
- 修复：将 `run.cmd` 重写为**纯 ASCII（英文注释与提示）**，彻底消除编码歧义与括号解析问题；逻辑不变（依赖检查 + .env 加载 + 模式选择/参数透传）。
- 教训：Windows 批处理文件若需中文提示，必须存为 UTF-8 BOM 且避免在 REM 注释中使用半角 `()`/`&`/`|`/`<`/`>`/`!`；最稳是保持纯 ASCII。Linux/macOS 的 `run.sh`（bash）无此问题。

## run.cmd 的 cmd 括号解析坑（同日补充）
- 现象：`run` 报 ". was unexpected at this time."，定位在依赖检查 `if errorlevel 1 (...)` 块附近。
- 根因：cmd 对 `if (...) (...) else (...)` 复合语句做括号匹配时**不识别引号内的圆括号**，会把块内 `echo ... (PyQt5 / openai).` 的 `openai)` 与 `set /p "...(y/N) "` 的 `)` 误当成最外层 if 块的结束括号，其后字符（如行尾 `.`）成为块外意外 token → 报错。`2>&1` 的 `&` 也是隐患。
- 修复：块内引号中的圆括号换方括号/冒号（`(y/N)`→`[y/N]`，`(PyQt5 / openai)`→描述去掉括号）；`>nul 2>&1`→`>nul 2>nul`；恢复 `@echo off`；标签 `::end`→`:end`。
- 教训：Windows 批处理任何 `if/for` 复合语句块内部，引号里的 `(` `)` 都会破坏括号匹配，必须 `^(` `^)` 转义或改用 `[]`/去掉；不能想当然认为引号能保护括号。

## gui.py 发送/排队交互（同日）
- 需求：发送后输入框不禁止，发送按钮在忙碌时变"排队"，点了把当前消息入队，上一条结束后自动发队首。
- 实现：`_set_busy(busy)` 不再禁用 inputEdit（保持可编辑），忙碌时 sendButton 文本切到"排队"且仍 enabled；on_send 忙碌分支改调 `_enqueue_current` 把当前输入加入 `self._queue`；抽出 `_dispatch(user_content)` 作为真正发请求的公共逻辑；`_on_success/_on_error` 末尾调 `_maybe_send_queued` 自动发队首。
- 根因回顾：之前焦点误跳到 imageEdit 是因为禁用 inputEdit/sendButton 触发 Qt 焦点转移到下一个可聚焦控件；现输入框保持可编辑 + 末尾 setFocus，问题解决。
- 排队管理增强（同日补充）：发送按钮忙碌时文案显示 `排队(N)` 数量角标（由 `_refresh_send_button` 维护，在 enqueue / dequeue / set_busy 时刷新）；发送按钮右键菜单"查看排队"打开 `QueueDialog` 列出排队消息预览，双击删除单条、可清空全部，关闭后按对象引用从 `self._queue` 移除并刷新角标（用对象引用而非下标，避免自动续发 pop 导致错位）。
- libpng iCCP 警告（同日）：`run gui` 启动时打印 `libpng warning: iCCP: known incorrect sRGB profile`，源于 gui.py 用 `QImage.loadFromData` 加载网络图片（_fetch_image），远端 PNG 自带不规范 sRGB profile。已在下载后加 `_strip_png_profile`（可选依赖 Pillow，重新编码 PNG 去 iCCP）消除；无 Pillow 时无害保留，可 `pip install pillow` 启用。
